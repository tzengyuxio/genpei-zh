# 翻譯風格指南

持續更新。語域、專有名詞政策、字庫缺口的處理、用語統一與格式限制都記在這裡。
系統用語的統一譯法在 [`translation/glossary.tsv`](../translation/glossary.tsv)。
基本做法沿用姊妹作 kami-zh（`~/works/kami-zh/docs/translation-style.md`），這裡只寫本作的定案與差異。

## 語域

題材是治承・壽永之亂（1180–1185）。整體定在**偏文言的古典白話**——像章回小說或歷史劇的口吻，不艱澀。
文本分三類，各用不同的語氣：

| 類別 | 例 | 寫法 |
|---|---|---|
| 系統訊息、戰報 | `平泉の商業値が%u上がりました` | 平實書面語：`平泉的商業値上升了%u` |
| 家臣進言、事件對話 | `申し上げます！平氏勢力は遠江にまで及んでおります` | 文言色彩較重：`啓稟主公！平氏勢力已擴及遠江` |
| 遊戲說明頁（`{C6}…説明{C7}`） | `朝廷は、１つの勢力が強大になりすぎるのを懸念し…` | 書面語，清楚優先 |

| `%s殿`（同輩、他家） | `%s大人` | 戰場上嘲諷敵將可用 `閣下` |

| `私` | `我`；對上位者 `在下` | |

## 專有名詞：保留日文漢字

**人名、名物、官位、地名一律照日文漢字原樣**，不改成繁體字形（`頼朝` 不寫 `賴朝`、`伊豆国府` 不寫 `伊豆國府`、`黒糸縅鎧`、`左衛門少尉` 照抄）。理由：

- 這些名字多半由程式從資料表（`extracted/text/main_data.tsv`、Sndata.gp）以 `%s` 帶入句子，劇情裡寫死的名字必須與帶入的一致，否則同一人在兩處寫法不同。
- 史料用字本身就是日文漢字，玩家查資料時也對得上。

劇情文字中**寫死的**人名、地名也照此辦理：`清盛`、`義仲`、`福原`、`坂東`、`遠江`、`奥州`、`渋谷重国` 都不改字形。

`main_data.tsv` 的**半形讀音保留不動**（武將情報畫面的小字讀音，如 `ﾐﾅﾓﾄ`）。`main_data.tsv` 因此整份不需翻譯。

**唯一例外是 390 號人物「かむろ」**：專有名詞裡只有它是假名，改成與系統用語一致的「禿童」（讀音 `ｶﾑﾛ` 照留）。Main.exe 內建表與 Sndata.gp 四個劇本各有一份，分別放在 `translation/main_data.tsv`、`translation/sndata.tsv`（只收這一筆）。

一般詞彙仍照「繁體優先」：`國家`、`戰場`、`選擇`。只有專有名詞例外。

## 字庫缺口的處理原則

JIS X 0208 是日文字集。文言、書面語幾乎無礙，口語是重災區。規則：

> **JIS X 0208 有繁體字形就用繁體，缺字時才退回日系新字體；新字體也不通順就換詞。**

注意 **cp932 能編碼不等於畫得出來**：NEC 第 13 區（0x87xx）與 NEC/IBM 擴充區（0xED–0xEE、0xFA–0xFC）的字在 DOS/V 字型沒有字模。`tools/patch.py`、`tools/message.py` 只做 cp932 編碼檢查，全面掃描要等 `tools/jis.py`（下一步移植）。

## 用語統一

系統用語（身分、資源、能力值、指令、合戰、系統訊息）一律照 [`translation/glossary.tsv`](../translation/glossary.tsv)。重點：

- 中日同形、中文也通的詞照用：`棟梁` `代官` `御家人` `兵糧` `財貨` `統治` `行軍` `菩提` `加護` `無常` `流鏑馬` `白拍子`。
- 中文不成詞的改譯：`相談役`→`參謀`、`知才`→`智力`、`勇名`→`威名`、`忠節`→`忠誠`、`勲功`→`功勳`、`調略`→`策反`、`物見`→`偵察`、`兵施`→`犒軍`、`誘兵`→`收買`。
- 字形不同的轉繁體：`拠点`→`據點`、`雑兵`→`雜兵`、`士気`→`士氣`、`宝物`→`寶物`、`軍団`→`軍團`。
- 系統：`セーブ`→`保存`、`ロード`→`讀取`、`ディスク`→`磁片`、`データ`→`資料`、`〜しますか?`→`是否〜?`、`よろしいですか？`→`如此可否？`。

新增用語先加進 glossary.tsv 再用，避免同一概念在不同畫面寫法不同。

## 標點

- 分句用「，」；「、」只用於並列的詞（`源氏、平氏`）。
- 刪節號用「……」（`・・・` → `……`），省寬度也比較像中文。
- 劇情（Message.gp）一律用全形「！」「？」，原文的半形 `?` 也改全形；EXE 的 UI 字串若原文是半形 `?` 且 bytes 很緊，可以照用半形。
- 全形空白（`　`）在選單裡是排版用的，照原文保留。

## 格式限制

### EXE 的 UI 字串（`tools/patch.py`，原地覆寫）

1. **不可超過 `max_bytes`**（全形 2 bytes、半形 1 byte）。
2. **選單字串用空白補齊來置中**：`'    新しくゲームを始める    '` 是 28 bytes。譯文要補回同寬並置中（`'         開始新遊戲         '`）；狀態欄的 `%3u` 等數字欄靠空白對齊，同理。
3. **`{C6}`/`{C7}` 色碼、`%s` `%3u` `%4d` 等參數原樣保留、順序不變**，`patch.py` 會比對。
4. 同一字串的所有位置（`offsets`）會一起改；同一原文在不同畫面要不同譯法時再拆列。
5. 對話框右上的小按鈕（讀檔畫面的「中止」、選棟梁的「決定」）是圖，不在文字檔裡。

### 劇情訊息（`tools/message.py`，整檔重建）

1. 長度不受原文限制（每個 block 上限 64 KB），**真正的限制是視窗大小**。`lines`、`max_cols` 欄是原文的行數與最寬一行（半形格；全形字、以及畫成全形的半形假名都算 2 格）。`apply` 超過時發 warning。原文 81% 的訊息每行 ≤ 28 格（14 個全形字），最寬 54 格；實機上對話框與旁白框會隨內容調寬（試譯「源頼朝大人，鎌倉有一名叫渋谷重国的人」38 格正常顯示），上限尚未測出，先以「不超過原文行寬」為原則。
2. 換行（`\n`）要自己重新斷：中文斷句與日文不同，照語意斷，不要照原文位置。
3. printf 參數（`%s %u %B1 %N1 %W1 %D1`）數量、種類、順序都不能變——錯了會讀錯參數、可能當機。中文語序需要把參數挪位置時，若同種參數有多個，要確認順序沒變（三個 `%s` 依序是什麼要看原文判斷）。
4. `{C6}…{C7}` 色碼原樣保留。
5. 訊息結尾的 `05 05 05` 由工具自動保留，TSV 看不到。

## 和歌

**決議（2026-10-06）：譯成中文詩句。**（另考慮過的「保留日文原文」「保留原文加註」不採用：中文玩家讀不懂古典日文。）

範圍：block 2 的 2-140～2-219，共 40 首（多為古今和歌集，依春、夏、秋、冬排列），每首拆成兩則：偶數 id 是上句（5-7-5），奇數 id 是下句（7-7）。例：

```
2-140  春来ぬと 人はいえども うぐいすの
2-141  鳴かぬかぎりは あらじとぞ思ふ
```

譯法原則：

1. **上下句一對一**：上句譯在上句、下句譯在下句，不能把整首意思全塞進其中一則。遊戲可能單獨顯示上句或下句（歌會、合戰中的「では、一首……」3-075／3-077），每則都要能單獨成句。
2. **用文言詩句**：定案為上下句各一句七言（見下方「定案譯法」），求意思準確、有詩味，不硬湊押韻。
3. **單行、不超過原文行寬**：原文每則都是單行、21–34 格（約 10–17 個全形字）。中文七言一句 14 格、五言兩句含空白 22 格，都在範圍內。不要加 `\n`。
4. **原文的句間空白**（`春来ぬと 人はいえども`）是 5-7-5 斷句；中文兩個短句之間可用全形空白「　」隔開，代替逗號。
5. **歌中的地名、名物照日文漢字**（吉野、龍田川、音羽山、大和撫子），與專有名詞政策一致。
6. 季語與典故（うぐいす＝黃鶯、ほととぎす＝杜鵑、女郎花、もみぢ＝紅葉）譯成中文讀者熟悉的意象。

### 實機用法（2026-10-06 確認）

歌會（外交 → 歌會 → 指派武將 → 決定）的流程：

1. 指派的武將說「では僭越ながら私が一句」。
2. **自動吟出一首**，玩家不用選。對話框兩行，第一行是上句，第二行是下句。
3. 後白河法皇講評（0-347／0-348）。
4. 「では次の歌會も…」，最後顯示朝廷關係的增減（0-340～345）。

引擎是把上句、下句**各自挑出來再拼成一首**。依據有兩點：

- 講評訊息裡有「下の句をお忘れ」（0-349）、「季節外れ」（0-350）、「上の句と下の句が合ってない」（0-351）。
- 每次吟的歌不同，1180 年 10 月實測吟到的都是冬歌：2-208/209、2-204/205、2-206/207。

所以上下句會被拆開配對，**每則都要能單獨成句**。合戰中的「では、一首……」（3-075／3-077）尚未實機看，推測用同一個顯示函式。

截圖存在本機 `docs/screenshots/`（gitignored）：`waka-kakai-ja.png` 是原文，`waka-kakai-zh.png` 是譯文。

### 定案譯法

**上下句各一句七言**，合起來是一聯：

```
2-204  初時雨 ふれば山辺ぞ おもほゆる  →  初時雨落憶山野
2-205  いづれの方か まづもみづらん      →  何處楓林先染紅
```

- 七言 14 格，比原文 21–34 格窄。中文七言沒有句中斷點，所以不用全形空白。
- 不押韻、不拘平仄，以意思準確為先。
- 字庫缺字照新字體：`黃→黄`、`蟬→蝉`、`歲→歳`、`絕→絶`。

## 文字圖（片頭／片尾）

片頭旁白、平家物語書法、片尾旁白是圖。譯文寫在 `translation/images.tsv`，由 `tools/textimg.py` 重繪：

- **旁白**（`narr`）：jiskan 24×24 點陣明朝體（`tools/fonts/`），直排，字距 26 px、欄距 32 px，頂端留 5 px。白色筆畫（色號 7）外加 2 px 外框（色號 14），和原圖相同。原版是 22 px 字面配 24 px 字距；jiskan 撐滿 24 px，所以字距加到 26 px 才有同樣 2 px 的字間空隙。每欄的字數受原圖尺寸限制：欄數 ≤ (寬 + 8) ÷ 32、每欄字數 ≤ (高 − 29) ÷ 26 + 1（高 256 → 9 字、272 → 10 字），欄與欄之間用 `/` 分隔，由右往左排。標點自動轉直排（「，、。」移到格子右上、「…」轉 90 度）。
- **大小上限**：新圖壓縮後不得大於原 chunk（原位寫回）。點陣字筆畫密、壓縮率較差，超過時 `textimg.py` 會報錯，換筆畫較少的同義字詞（例：片尾「長年戰亂終結」→「長年戰亂告終」）。
- 譯文不必貼齊日文原文的長度，為了放進版面，每欄可比原文少 0～2 字。
- **書法**（`brush`）：楷體，一欄，字距平均分配。
- 平家物語的名句採通行的中文譯法：祇園精舍之鐘聲，有諸行無常之響；沙羅雙樹之花色，顯盛者必衰之理。
- 圖不受 JIS 字庫限制，用正規繁體（`頼朝` 等人名仍照日文漢字）。
- 標題「源平合戦」是商標字，保留不改。
